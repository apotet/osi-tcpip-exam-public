Точка захвата: Ethernet-интерфейс узла A (192.0.2.10 /24, MAC 02:00:00:00:00:10), входящий и исходящий трафик. B — 192.0.2.20, C — 192.0.2.30; все в одном Ethernet-сегменте /24. Шлюз не участвует.

A сначала узнаёт MAC B через ARP и делает ping, затем узнаёт MAC C и делает ping. Начальные ARP-записи B/C у A отсутствуют; B и C узнают A из его запросов. Файл содержит весь этот синтетический обмен за 0,103 с, без фонового трафика.

Восемь кадров

Выбери карточку, затем перейди к полям. Номера совпадают с Wireshark; время — от начала трассы.

    Поля кадра

    Названия — поля Wireshark. Числа в основном десятичные; EtherType и checksum — шестнадцатеричные. Статус checksum 1 означает «верна». ARP не содержит IP-заголовка и своей контрольной суммы.

    Повтори в Wireshark

    1. Скачай pcap и открой через File → Open. Захват с сетевой карты запускать не нужно.
    2. Очисти строку display filter и сортируй по No. по возрастанию: должно быть 8 кадров. Выбери View → Time Display Format → Seconds Since Beginning of Capture.
    3. Найди номер из задания. В Packet Details раскрой Ethernet II, Address Resolution Protocol либо Internet Protocol Version 4 и Internet Control Message Protocol. При выборе поля его имя видно в строке состояния.
    4. Для пары 3/4 или 7/8 сравни IPv4 Source/Destination, ICMP Type, Identifier (BE) и Sequence Number (BE). BE — порядок байтов сети; здесь Identifier 4660 или 22136, Sequence 1.
    5. При желании включи проверку IPv4 checksum в Preferences → Protocols → IPv4. Длины кадров — 60 байт без Ethernet FCS; FCS, преамбула и межкадровый интервал в файл не включены.

    Ответ на ping подтверждает только видимый ICMP-обмен. Файл не проверяет доступность веба, реальную сеть или оборудование. Фильтры и диагностика не входят в этот пакет.
