## Перед включением

1. Открыть настройки счётчика **23177221** в https://metrika.yandex.ru/ и указать
   текущий адрес сайта `https://apotet.github.io/osi-tcpip-exam-public/`. Проверить
   дополнительные адреса, ограничения по адресам и фильтры старого сайта.
   Старая история останется в этом счётчике; данные нового сайта отличать по
   дате публикации и URL. Новый счётчик нужен только при желании разделить историю.
2. ID уже установлен в `analytics/config.js`. Для отключения поставить null:
   SDK не загрузится, события не отправятся. Не вставлять дополнительный
   стандартный snippet в HTML: общий loader уже существует.
3. В настройках счётчика создать цели типа **JavaScript-событие** с точными
   идентификаторами: `exam_start`, `exam_complete`, `training_open`, `ipv4_open`,
   `ipv6_open`, `cli_open`, `cheatsheet_open`.
   Названия целей для человека могут отличаться; идентификаторы — нет.
   `feedback_submit`, `troubleshooting_open`, `pro_interest`, `b2b_interest`
   зарезервированы, но пока не активны и не должны иметь ложных достижений.
4. Проверить настройки счётчика в кабинете: не включать Webvisor, автоматические
   цели форм, сбор содержимого форм и дополнительные интеграции без отдельного решения.
   Код отключает Webvisor, clickmap, trackLinks, accurateTrackBounce, trackHash,
   ecommerce, childIframe и отправку заголовков.
5. **Privacy / юридическое решение:** владелец должен определить применимые
   требования к уведомлению, согласию, cookies и политике конфиденциальности для
   своей аудитории и юрисдикций. Маленький текст об аналитике не является согласием
   и не доказывает соблюдение закона. Если потребуется предварительное согласие,
   до его реализации вернуть `counterId: null`. Интеграция подготовлена независимо
   от этого решения; production пока не содержит новый модуль.
6. Отдельно подтвердить публикацию. Настройка ID и публикация не выполняются
   автоматически по этому документу.

## Что автоматически не доказано

- Приём реальным счётчиком, задержки обработки, доступность Яндекса из сетей
  пользователей, правильность прав и настроенных целей. Тесты используют spy.
- Реальный iPhone Safari/Chrome: Playwright WebKit не является Safari на iOS.
- Cookies, IP и технические идентификаторы реального SDK: приложение не передаёт
  персональные поля в событиях, но это не делает сервис анонимным или без cookies.
- Ручной `hit` содержит origin + pathname, без query/hash, title и referrer.
  Это проверка наших аргументов, а не обещание, что внешний SDK не собирает
  техническую информацию или URL другими средствами. Проверить Network после включения.
- Полнота данных при блокировщиках, offline, ошибке SDK и переполнении очереди.
  Данные могут теряться; сайт не должен зависеть от их доставки.

## Checklist после разрешённой публикации с настоящим ID

На **iPhone Safari**, **iPhone Chrome** и **desktop Chrome** повторить таблицу ниже.
Сначала без блокировщика, затем с блокировкой `mc.yandex.ru` или offline после
загрузки страницы. Не требуется ставить приложение на устройство или менять UX.

| Действие | Ожидаемое событие / параметры | Где смотреть в Метрике |
|---|---|---|
| Начать экзамен, включая быстрый двойной клик | `exam_start`: mode; одно достижение на попытку | Отчёты → Конверсии → цель exam_start; mode — в отчёте «Параметры визитов» |
| Ответить только на часть; reload или выйти | Нет `exam_complete`; reload не создаёт exam_start | Конверсии → exam_complete; убедиться, что достижение не появилось |
| Завершить 10 ответов и открыть результат | `exam_complete`: mode, score, total=10, percent, passed; ровно одно | Конверсии → exam_complete; параметры — «Параметры визитов» |
| Завершить ниже и выше порога 8/10 | passed=false / true, percent соответствует score | Конверсии и «Параметры визитов» |
| Нажать «Ещё раз» | Один новый exam_start; прежний complete не повторяется | Конверсии → exam_start / exam_complete |
| Открыть IPv4 | `ipv4_open`, без параметров; тренажёр работает | Конверсии → ipv4_open |
| Открыть IPv6 | `ipv6_open`, без параметров; тренажёр работает | Конверсии → ipv6_open |
| Открыть CLI, затем сменить вендора | Один cli_open; дополнительных целей кликов/вендоров нет | Конверсии → cli_open |
| Открыть обучение повторным быстрым кликом | training_open один при переходе; новый при реальном возврате в раздел | Конверсии → training_open |
| Открыть краткий справочник или шпаргалку | cheatsheet_open: section=learning, topic — заголовок уровня | Конверсии → cheatsheet_open; параметры — «Параметры визитов» |
| Открыть разбор после ответа / автоматическую учебную карточку | cheatsheet_open: section=exam, topic — тема вопроса; закрытие не считается | Конверсии → cheatsheet_open; параметры — «Параметры визитов» |
| Back/Forward между разделами | Нет повторного *_open от восстановления истории | Конверсии соответствующей цели; проверить также Network / Console |
| Заблокировать Метрику / выключить сеть после загрузки | Экзамен, локальные задания и уже загруженный CLI работают | Console: нет исключений приложения; статистика может отсутствовать |
| Проверить будущие направления и обратную связь | Нет feedback_submit / troubleshooting_open / pro_interest / b2b_interest | Конверсии; их не должны отправлять текущие действия |

В кабинете отчёт может называться «Параметры визитов» / «Параметры посетителей»
в зависимости от текущей версии интерфейса; нужны именно параметры визитов,
переданные аргументом reachGoal. Они описывают визит, а не гарантированную таблицу
каждого отдельного события. Для точного числа вызовов и аргументов при ручной
диагностике дополнительно использовать Console/Network и официальный режим
отладки счётчика (см. документацию ниже). Отчёты обновляются с задержкой;
фильтры роботов, часовой пояс и сегмент могут влиять на видимые достижения.
