## Подтверждённые замечания

| Область | Подтверждение и решение для редактора |
|---|---|
| Подсказка через topic | `l6-02` спрашивает уровень преобразования кодировок, а badge заранее содержит `L6 · Представления`. Это прямое раскрытие ответа. Проверить все badge, но не считать любую подпись уровня утечкой: `k-09` уже называет транспортный уровень в условии и спрашивает PDU TCP. |
| Слово из ответа в вопросе | `l2-04` содержит flooding в условии; `tr-06` спрашивает фильтр ARP и предлагает `arp`. Второе может быть допустимой базовой проверкой синтаксиса, поэтому сложность нужно согласовать, а не объявлять факт неверным. |
| Слабые варианты | `gen-diag-3` содержит `ip.port = 502`, `modbus.port only`, `ether.port == 502`; `gen-diag-4` — `ping.port`, `ip == icmp`, `tcp.icmp`. Правильные фильтры в текущем ключе корректны; проблема в вымышленных дистракторах. Аналогично ICMP/ARP легко отсекаются в транспортных вопросах. |
| Повторы | `tcp-02` / `new-tcpip-map`, `l4-10` / `new-l4-flow` проверяют практически один факт. Первая пара уже объединена через `family`, исключающую одновременное попадание в экзамен; это не удаляет повтор из банка. |
| Группировка портов | UDP-вопросы `gen-port-6…9,11,13,14` находятся в `l5-l7`, а TCP-вопросы — в `l4`. Соответствующие `gen-transport-*` находятся в `l4`. Нужна единая редакторская политика: наличие UDP само по себе не делает приложение уровнем L4. |
| Формулировки и сложность | Длина правильного варианта, абсолютные утверждения и очевидные отвлекающие ответы требуют ручного прохода. Они снижают различающую способность теста, но сами по себе не доказывают неверность ключа. |

## Замены, которые нельзя переносить без исправления

| ID / предложение Claude | Риск и необходимая оговорка |
|---|---|
| `l4-10` / `new-l4-flow`: две вкладки одного HTTPS-сайта отличаются исходным TCP-портом | Вкладки могут совместно использовать одно TCP-соединение, а HTTP/3 использует QUIC. Указать **два различных одновременных TCP-соединения к одному IP и порту сервера**, а не две вкладки. |
| `tr-01`: Link поднят и шлюз отвечает на ping, значит L1–L3 исключены | Доступность локального шлюза не доказывает маршрут до удалённого сервера, отсутствие потерь или фильтрации. Предложенная замена создаёт ложный диагностический вывод. |
| `gen-diag-8`: неверный ответ «порт назначения» | Классический UDP traceroute также меняет destination port. Спросить, какое поле ограничивает число маршрутизаторов, и не противопоставлять два одновременно изменяемых поля. |
| `l3-11`: заменить вопрос о полном диапазоне на допустимые адреса хостов | Текущий вопрос явно говорит «полный диапазон … включая broadcast». Его ключ `.0,.1,.14,.15` корректен. Замена меняет проверяемое умение; это не исправление неверного ключа. |
| `gen-diag-4`: `ipv6.addr` как сомнительный фильтр | Имя поля без оператора — допустимая проверка наличия поля. Такой вариант не является вымышленным синтаксисом; он показывает IPv6-трафик шире ICMPv6. |
| `gen-diag-3`: `tcp.dstport == 502` показывает «только запросы» | Фильтр проверяет порт назначения, а не семантический тип сообщения приложения. Нужна точная формулировка про направления потока. |
| Заменить ICMP/ARP во всех `gen-transport-*` на SCTP и «TCP и UDP в равной мере» | Универсальная подстановка не обеспечивает правдоподобных вариантов. DNS допускает TCP и для обычного, неусечённого запроса; «в равной мере» не задаёт проверяемого условия. Указывать конкретный сценарий. |
| Объявить `tcp-05`, `tcp-06`, `new-tcpip-router` полными дублями | `tcp-06` — multiple choice про сохраняемые поля, другие — про заменяемые L2-поля. Есть тематическое перекрытие, но разные умения. Не удалять автоматически. |
| `l4-06`, `gen-port-1`, `gen-transport-1` | Первые два спрашивают порт, третий — транспорт. Все уже имеют одну `family=service-1`; удаление всех повторов может потерять отдельное умение. |
| ICMP: сомнение из-за вложения в IP | Вложение протокола в IP само по себе не доказывает принадлежность к уровню выше L3. ICMP — часть функций Internet layer; разделять OSI и TCP/IP. |
| `l1-04`, access VLAN, ARP, MRP, TLS/QUIC | Проверить условия измерения Rx, тип оптики, поведение оборудования, proxy ARP, профиль MRP и модель уровней. Некоторые новые дистракторы снова содержат абсолюты и посторонние уровни. |

Нейтральные topic следует выбирать по конкретному проверяемому факту.
Переименование всех тем без проверки не устраняет подсказку, если её оставляет
условие, название режима, фотография или подпись к ней.
Проверка фотографических вопросов также должна учитывать `imageAlt`:
например, у `photo-lc` он уже называет LC. Не удалять доступное описание
автоматически; согласовать нейтральное описание, сохраняющее доступность.

## Проверка перемешивания

В исходном банке 310 из 325 single choice имеют `correct=[0]`. Это индексы
исходного массива, а не места на экране. `index.html` применяет Fisher–Yates
при `startQuiz` и сохраняет `original` в значении radio/checkbox. Оценивание
сопоставляет исходные индексы с `correct`, а не экранные позиции.
Перемешивание выполняется при начале каждой новой попытки, для single и multi.
Повторный рендер того же вопроса в текущей попытке не должен менять порядок.
Случайность допускает совпадение порядка между попытками и правильный ответ
на первом месте; нельзя требовать гарантированного изменения каждый раз.

Дополнительная браузерная проверка: `verify-shuffle.cjs`. Она запускает реальный
UI Chromium 390×844 с контролируемыми копиями двух реальных записей (`l1-01`,
`l1-04`) и детерминированным RNG. Проверяются соответствие текста исходному
индексу, radio/checkbox, изменение порядка, правильные/неправильные ответы и
итоговый score. Это проверка механизма, **не содержательной истинности ключей**
и не полный новый прогон матрицы Stage 1.

Raw JSON и traces: `audit/runs/claude-review-20261004/`.
Завершённый запуск: **2 pass, 0 fail, 0 skip**; 80 показов вопросов,
8 попыток с ожидаемым результатом 5/10. Получено 23 различных порядка
для single choice и 39 для multiple choice. Результат:
`shuffle-results.json`; traces: `l1-01-shuffle-trace.zip`,
`l1-04-shuffle-trace.zip`. Каталог raw-данных исключён из Git.
Команда повторения из корня репозитория при работающем локальном сервере 4173:
`AUDIT_RUN_DIR=<новый-каталог> node audit/claude-review/verify-shuffle.cjs`.
Первоначальная ошибка сравнения массивов из разных VM-контекстов — ошибка
проверочного скрипта, исправлена; результаты того запуска отдельно в
`setup-attempt/` и не суммируются с завершённым прогоном.
