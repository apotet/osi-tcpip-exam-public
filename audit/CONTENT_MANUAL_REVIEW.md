## Применённые технические ограничения замен

- `l4-10`: две вкладки заменены **двумя различными одновременными TCP-соединениями**
  к одному IP и порту. Это устраняет ложное предположение, что вкладки требуют
  разных соединений. Удалён только прямо указанный `new-l4-flow`.
- `tr-01`: успешный ping локального шлюза не исключает удалённую проблему L3.
  Проверяется путь, фильтрация и служба, а не вывод «L1–L3 работают».
- `gen-diag-8`: вопрос спрашивает поле, ограничивающее число L3-переходов.
  У классического UDP traceroute также может меняться порт назначения.
- `gen-diag-3`: последний дистрактор `ip.proto == 502` заменён на реальный
  `tcp.srcport == 502`, потому что номер IP Protocol ограничен 8 битами.
  Пояснение описывает поля заголовка, а не обещает распознавание запросов.
- `gen-diag-4`: `ipv6.addr` оставлен как валидная проверка наличия поля,
  которая не выбирает исключительно ICMPv6.
- `l3-11`: исходный полный диапазон /28 был корректным. По прямой просьбе
  пользователя принят предложенный вопрос о **назначаемых адресах хостов**;
  ключ изменён вместе с условием, а не объявлен прежней технической ошибкой.

Картинки, текст внутри них, CLI-каталог, логика статистики/localStorage,
архитектура и будущие функции не изменялись. Повторные снимки у сохранённых
вопросов не объявляются дефектом автоматически: решение об удалении остаётся
по конкретным ID и указаниям авторов аудита.
